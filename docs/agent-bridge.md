# Claude·Codex 핸드오버와 교차 리뷰

## 사용하기

양쪽 사용자 스킬 경로에 `agent-bridge`를 설치한 뒤 새 세션에서 다음처럼 요청한다.

> agent-bridge로 현재 작업을 등록하고 Claude에 넘길 핸드오버를 준비해줘. 완료한 일, 남은 일, 검증 결과와 다음 행동을 남겨줘.

받는 세션에는 생성된 공통 작업 폴더의 **절대 경로**와 작업 ID를 전달한다.

> agent-bridge로 이 작업 폴더의 기록과 실제 Git 상태를 확인하고 인수해줘. 인계 문서에 적힌 다음 행동부터 이어가줘.

리뷰는 다음처럼 요청한다.

> agent-bridge로 현재 변경을 다른 모델에 리뷰 요청해줘. 결함은 직접 확인해서 반영 여부와 근거를 정리해줘.

기존 세션에서 스킬이 발견되지 않으면 아래 설치 위치의 `SKILL.md`를 직접 읽도록 요청한다.

- Codex: `~/.agents/skills/agent-bridge/SKILL.md`
- Claude Code: `~/.claude/skills/agent-bridge/SKILL.md`

상태 저장 위치는 작업마다 같아야 한다. Kuru 권장 위치는 `kuru/worktrees/.agent-bridge`다. 이 디렉터리는 Git에 커밋하지 않는다. 상세 명령은 [스킬](../skills/agent-bridge/SKILL.md)을 참고한다.

## 인계 문서 예시

```markdown
# 작업 인계
- 목표/완료 조건:
- 티켓/PR:
- 완료한 일:
- 남은 일과 막힌 이유:
- 결정과 근거:
- 검증 명령/결과/대상 SHA:
- 미커밋·미추적 파일 설명:
- 다음 첫 행동:
- 개발 서버 포트/PID:
- 사용자 승인 근거와 범위:
- Git에서 무시된 환경 파일/의존성 차이 (비밀값 제외):
```

인계 기록은 대화 전체를 복제하지 않는다. 다른 에이전트가 바로 이어갈 수 있는 현재 상태를 남긴다. 인계 후 기존 담당자는 수정하지 않고, 새 담당자는 `accept` 성공 후 수정한다. 프로세스 강제 종료·코드 변경 등으로 인수가 거부되면 기존 담당자가 상태를 확인한 뒤 인계 문서를 재발행한다.

## 결과 해석

| 상태 | 의미 |
|---|---|
| prepared | 리뷰 요청 파일만 생성, 모델 미호출 |
| running | CLI 실행 중; 강제 종료된 실행이면 이 상태가 남을 수 있음 |
| completed | 리뷰 응답 수신. 승인이나 테스트 통과를 뜻하지 않음 |
| stale | 리뷰 도중 코드 변경 감지, 재검토 필요 |
| failed | CLI 부재, 인증/실행 오류, 시간 초과 또는 결과 형식 오류 |
| interrupted | 사용자 중단 감지. 로그와 상태 보존 |

리뷰 결과는 요청별 폴더에 남으며 커밋 SHA를 포함한다. 새 커밋을 만들면 과거 리뷰를 현재 코드의 검증 근거로 사용하지 않는다. 실행 도구는 코드 수정·외부 게시·머지·배포를 수행하지 않는다. 설정된 CLI의 인증/모델을 사용하며 GUI의 기존 세션을 깨우지 않는다.

## 설치와 유지보수

정본은 `agent-common-workflow/skills/agent-bridge`다. 스크립트도 스킬 폴더에 들어 있어 양쪽에 동일한 폴더를 복사하면 된다. Python 3.10 이상과 Git이 필요하며 자동 리뷰에는 해당 도구의 인증된 CLI가 필요하다. Windows는 네이티브 실행 파일을 사용한다.

일반 공통 동기화는 기존 `tools/sync-agent-skills.sh`를 사용한다. 단 이 스크립트는 사용자 스킬 폴더 전체를 교체하므로, 다른 사용자 스킬을 보존하려는 개별 설치에서는 **agent-bridge 폴더만** 복사한다. 브랜치 버전을 먼저 설치했다면 해당 변경이 main에 반영되기 전 구버전 main으로 전체 동기화할 경우 새 스킬이 삭제될 수 있다.

## 검증

`python -m unittest discover -s tests -p test_agent_bridge.py -v`

임시 Git 저장소와 가짜 CLI 응답으로 담당자 전환, 미추적 파일 내용 변경, 잠금, 실패·시간 초과·오래된 리뷰·중단 상태를 검증한다. Windows 실제 자식 프로세스로 시간 제한과 부모 선종료도 검증한다. 이 테스트는 인증된 모델의 실제 리뷰 응답을 대신하지 않는다.
