# 내부 공유 페이지 게시 (Claude Artifact)

코드에서 나온 사실(문구·단계·조건·화면)을 사람이 보는 페이지로 공유할 때의 규칙. 페이지는 게시물일 뿐이고 **정본은 레포**다.

## 언제 쓰나

- 앱 알림·메일 템플릿·사용 가이드처럼 "코드에 있는 문구와 조건을 화면 목업·번역과 함께" 보여 줄 때
- 이미 게시된 페이지의 원본(코드·문구)을 바꿨을 때 — 같은 PR 에서 재게시까지가 한 작업이다
- 시안·일회성 분석 페이지는 이 스킬의 동기화 규칙 대상이 아니다(게시만 하고 URL 을 티켓에 남긴다)

## 구조 — 원본 → 생성물 → 같은 URL 재게시

| 층 | 위치(권장) | 관리 |
|---|---|---|
| 카탈로그 | `docs/<주제>/catalog.json` | **코드에서 생성**. 테스트가 실제 정의를 읽어 쓰고, 낡으면 테스트 실패 |
| 사람 관리 입력 | `tool/<주제>-gallery/*.json` | 번역·설명·배포 상태(`release`) |
| 생성기 | `tool/<주제>-gallery/build.mjs` | 의존성 없는 Node. 누락(번역·설명·목업) 시 `--strict` 로 실패 |
| 게시본 | `docs/<주제>/gallery.html` | 생성물. 코드와 같은 커밋 |
| 정본 문서 | `docs/policy/`·`docs/dev/` | 규칙과 절차. 게시 URL 을 여기에 적는다 |

- 문구를 화면 코드에 흩어 두지 않는다. 카탈로그 테스트가 읽을 수 있는 정의 파일에 모은다.
- 게시본은 생성물을 그대로 올린다. 페이지에서 직접 고치지 않는다(다음 생성 때 사라진다).

## 게시·갱신 절차 (Claude 세션)

1. 카탈로그 갱신 → 생성기 `--strict` 실행 → 생성물 커밋.
2. **처음 게시**: Artifact tool 로 `gallery.html` 게시. 비공개로 시작한다. 받은 URL 을 개발 문서·인덱스 레포 게시본 목록에 기록.
3. **갱신**: 반드시 **기존 URL 로 재게시**한다. 같은 세션이면 같은 파일 경로, 다른 세션이면 `url` 을 넘긴다. URL 없이 게시하면 새 페이지가 생겨 링크가 갈라진다.
   - 덮어쓰기 방지: 게시할 때 publish `label` 에 원본 커밋 SHA 를 적고, 문서의 게시 URL 옆에 마지막 게시 SHA·시각을 남긴다.
   - 다른 세션에서 갱신할 때는 먼저 read 해서 라이브 버전의 SHA 를 내 원본과 비교한다. 라이브가 내 원본에 없는 변경을 담고 있으면 그 변경을 원본에 먼저 통합한 뒤 재생성·재게시한다. 오래된 작업본으로 덮지 않는다.
4. 운영 반영 상태가 바뀌면(PR → 머지 → 배포) `release` 와 문서 상태 줄을 갱신하고 재게시. 미머지 기능을 적용 완료로 쓰지 않는다.

## 권한

| 주체 | 보기 | 재게시 |
|---|---|---|
| 소유자 계정의 Claude | 가능 | 가능 |
| 공유받은 내부 사용자(사람) | 가능 | 편집 권한을 받은 경우만 |
| 공유받은 내부 사용자의 Claude | URL 로 read 가능 | 편집 권한(writer)이 있을 때만. 없으면 갱신 대신 새 페이지가 생기므로 **게시하지 말고 소유자에게 요청** |
| Claude 이외 에이전트(Codex 등) | 현재 연결된 도구 기준 직접 불가 | 현재 연결된 도구 기준 직접 불가 |

- **공유 범위·편집 권한은 에이전트가 바꿀 수 없다.** 소유자가 페이지 Share 메뉴에서 내부 사용자(조직)에게 공유하고, 갱신 담당이 있으면 편집 권한까지 준다. 처음 게시한 뒤 이 설정이 필요하다고 사용자에게 알린다.
- 원본은 레포에 있으므로 레포 권한이 있으면 누구나 고칠 수 있다. 막히는 것은 재게시뿐이다.

## 공유가 막히는 페이지 (2026-10-07 이 환경에서 실측한 제한)

- iframe(`srcdoc`)이 든 버전에서 초대(이메일) 공유가 막히는 것을 확인했다 — Share 메뉴에 「이 버전은 초대를 통해 공유할 수 없습니다」, 재게시·새 페이지도 같았다(메일 갤러리). 그래서 **현재는 iframe 을 쓰지 않는다.** 정책이 바뀌었을 수 있으니 막히면 이 항목부터 의심하고, 풀렸으면 이 절을 고친다.
  - 대안은 Shadow DOM: 원문을 `<template>` 에 넣고 스크립트로 `attachShadow({mode:"open"}).innerHTML = template.innerHTML`.
  - Shadow DOM 은 **CSS 범위 분리일 뿐 iframe 과 같은 화면을 보장하지 않는다.** html·body 스타일은 사라지므로 배경·여백을 호스트에 지정하고, 화면폭 미디어쿼리(viewport 기준)는 컨테이너 쿼리로 바꾸고, 높이는 `height:auto`, 링크는 `target="_blank"`.
  - 전환 후 대표 템플릿 몇 개로 배경·폰트·너비·링크·좁은 폭 레이아웃이 iframe 버전과 같은지 대조한다.
  - 이미 초대가 된 페이지는 같은 URL 로 iframe 없는 버전을 재게시해 채운다.
- 외부 사이트 이미지는 뷰어 CSP 로 차단된다(게시 시 경고). 보여야 하는 이미지는 data: URI 로 넣는다.

## Claude 이외 에이전트가 원본을 고쳤을 때

1. 카탈로그·생성물까지 갱신해 커밋한다(생성은 로컬 명령이라 가능).
2. agent-bridge 로 Claude 에 인계: 작업 ID, 커밋 SHA, 게시 URL, "재게시 필요". 상태를 "게시 완료"로 쓰지 않는다.
3. 인수한 Claude 가 해당 URL 로 재게시하고 결과를 인계 기록에 남긴다.

## 게시 금지

- 비밀값, 고객 실데이터, 계정 화면 캡처. 화면은 예시 데이터 목업으로 그린다.
- 실존 조직·인물을 사칭하는 페이지.
- 리뷰 로그·코드 원문 덤프(필요한 사실만 요약).

## 완료 기준

- [ ] 카탈로그 테스트 통과, 생성기 `--strict` 누락 0
- [ ] 생성물 커밋, 기존 URL 로 재게시(새 URL 이 생기지 않음), label·문서에 원본 SHA·게시 시각
- [ ] 게시 결과의 경고 확인(외부 이미지 등) — 남긴 경고는 이유를 보고에 적음
- [ ] 게시 뷰어에서 렌더링 확인(이미지·레이아웃·좁은 폭)
- [ ] 처음 게시라면 공유·편집 권한 설정을 사용자에게 안내하고, 초대 공유가 되는지 사용자 확인을 받음
- [ ] 수신자 쪽 열람을 직접 확인하지 못했으면 "미검증"으로 보고
- [ ] 개발 문서·게시본 목록에 URL·생성 명령이 있음
