# 화면 시안 — 실제 화면 캡처 + Design 캔버스

시안은 "바뀐 뒤 화면을 그대로 그려 볼 수 있어야" 판단에 쓸 수 있다. 그래서 **실제 화면을 캡처해 바탕에 깔고, 바뀌는 자리에만 새 부품을 그린다.** 뭉뚱그린 상자나 예시 화면은 그리지 않는다.

## 형식

- **캔버스**: Artifact `quickstart` → `intent: "design"` 으로 Design 타입 캔버스를 만든다. 장면(상태)마다 아트보드 하나.
- **바탕**: 실제 화면 캡처를 에셋으로 올리고(`publish`, `asset:true`) 아트보드 전체에 `<img>` 로 깐다.
- **새 부분**: 바뀌는 영역만 같은 좌표에 새 마크업을 덮는다. 그 아래 기존 내용은 같은 캡처를 `background-position` 으로 잘라 이어 붙여 "밀려 내려가는" 모습을 보여 준다.
- **대화상자·오버레이**: 바탕 아트보드를 `<dc-import>` 로 불러오고 그 위에 띄운다(같은 화면을 다시 그리지 않는다).
- **장면**: 기본(접힘) → 펼침 → 입력·확인 대화상자 → 완료·예외 상태처럼, 사용자가 실제로 지나가는 순서대로 3~5장.
- **값**: 색·글꼴·간격은 그 앱의 디자인 토큰 값 그대로. 문구는 운영 언어 그대로. 숫자는 샘플이라고 캔버스 제목에 적는다.

## 캡처 절차

1. 최신 `origin/dev` + 작업 브랜치로 로컬 실행(dev API). Flutter 웹은 **release 모드**로 띄운다 — 디버그 서버는 처음 연결한 탭만 받는다.
2. QA 브라우저(`e2e-qa` 스킬)로 연다. 다른 세션과 겹치지 않는 CDP 포트를 쓰고 `127.0.0.1` 로 붙는다. 로그인 인증 코드만 사용자에게 요청한다.
3. 운영자가 쓰는 **언어·창 폭**(데스크톱 관리 화면이면 1920 폭)으로 맞추고, 튜토리얼·공지 같은 오버레이를 닫은 뒤 캡처한다.
4. 데이터가 있는 날짜·계정을 고른다(빈 화면 캡처 금지).

## 예외

- **실물이 없는 새 화면**만 캡처 없이 그린다. 이때도 같은 앱의 기존 화면 캡처에서 색·크기·부품을 가져온다.
- 배치만 비교하는 여러 안이면, 가능하면 실제 코드로 각 안을 띄워 캡처한 것을 아트보드로 나란히 놓는다.
- 설명서·정책서·QA 기록처럼 읽는 페이지는 시안이 아니다 — `artifact-publishing` 스킬.

## 전달

- 캔버스 링크와 함께 장면별 한 줄 설명(`#artboard-<이름>` 링크)을 준다.
- 기존 안(요청자가 준 시안 등)이 있으면 같은 점·다른 점과 이유를 짧게 붙인다.
- 공유 상태를 확인해 알린다 — 비공개면 다른 사람이 열 수 없다.
